# Offline research suite

Start with `../docs/RESEARCH_PLAN.md` for questions and limitations and `../docs/RESEARCH_RESULTS.md` for the verified run. All new evidence is synthetic.

From the project root, using Python 3.12:

```bash
python -m pip install -r research/requirements.txt
python -m unittest discover -s research/tests -v
python -m research.study --seeds 5 --episodes 240 --models hgb lr --out research/results_reproduction
python -m research.verify_results research/results_reproduction
python -m research.analyze_control research/results_reproduction
python -m research.plots research/results_reproduction
python -m research.write_report research/results_reproduction --out docs/RESEARCH_RESULTS_REPRODUCTION.md
```

No web server, database, pretrained model, external data or network access is used by the experiments. The small offline loader reads the application's original feature/monitoring leaf modules without importing its web app. The application and deployed model are not changed by running this suite.

Results are written after each arm; check completion rather than assuming any existing CSV is a full study. Never overwrite a completed run. Default configuration: 24 weeks, 240 episodes/week, three events per episode, 4% fraud episodes, 0.8 adaptation strength, 0.5% label adjudication noise, 5% weekly offline ranking budget. See `study.py --help` for parameters. The synthetic generator is deterministic per seed; RNG draws are shared between stationary and drift arms.

For a quick smoke run use `--seeds 1 --episodes 80 --models hgb` and a new output directory. A one-seed run cannot estimate cross-seed uncertainty. For confirmation use `--seed-start 100 --seeds 10` after freezing the simulator/protocol; that still tests the same synthetic world.

Sensitivity examples, each with its own output directory:

```bash
python -m research.study --seeds 5 --fraud-rate .01 --out research/results_prevalence01
python -m research.study --seeds 5 --adaptation-strength 0 --out research/results_mix_only
python -m research.study --seeds 5 --label-noise 0 --out research/results_clean_labels
```

These sensitivity runs are proposed, **not included as completed experiments**. No new monitor has been validated, and no real UPI outcomes are evaluated.

## Output files

| File | Meaning |
|---|---|
| `completion.json` | Verified expected combinations, row counts and source integrity |
| `protocol.json` | Configuration, versions, command and initial source hashes |
| `diagnostics.json` | Data digests, fraud prevalence, graph activity, univariate novelty AUC |
| `weekly_metrics.csv` | Every seed/arm/model/strategy/week |
| `summary.csv` | Phase means and t intervals over seed means |
| `paired_control.csv` | Paired difference in differences |
| `paired_delay.csv` | Adapted-phase instant-minus-three-week label recall; generated by write_report |
| `paired_strategies.csv` | Adapted-phase strategy-minus-fixed differences |
| `monitoring.csv` | Per-week distribution diagnostics and retrospective fixed recall |
| `monitor_per_seed.csv` | Exploratory harmful-week coverage and alarm timing |
| `monitor_summary.csv` | Seed-level monitoring summary |
| `figures/*.png` | Regenerable scientific plots |

Primary quantities are recall at exact weekly review capacity and average precision. Ranking uses the full week's scores; it is an offline evaluation measure rather than an online policy. Label delays are enforced before fitting; eventual latent truth is used for evaluation only. The plan describes remaining simulator shortcuts and the distinction between representative labels and selected investigator feedback.
